# Intelligent Traffic Signal Agent

An interactive traffic simulation that compares fixed-time traffic signals with an AI-based signal controller. The project models vehicles at multiple junctions, tracks queues and waiting time, and supports emergency-vehicle routing using A* pathfinding.

## Features

- **Interactive traffic simulation:** Visualizes roads, vehicles, junctions, and traffic signals using Pygame.
- **AI signal control:** Selects signal phases based on traffic queues and waiting information.
- **Fixed-time control:** Provides a baseline controller for comparison with AI mode.
- **Traffic scenarios:** Switch between normal and peak traffic.
- **Emergency vehicles:** Identifies emergency vehicles and uses A* pathfinding for bypass routing.
- **Traffic logging:** Records simulation snapshots in `traffic_data.csv`.
- **Analytics dashboard:** Uses Streamlit, Pandas, and Matplotlib to explore vehicle counts, directional queues, signal states, and cumulative waiting time.
- **Controlled experiment:** `experiment.py` runs a fixed-versus-AI experiment and stores its results.
- **Tests:** Includes tests for the signal agent and routing logic.

## Requirements

- Python 3.10 or newer recommended
- Windows, macOS, or Linux
- A desktop environment for the Pygame window

## Installation

### Windows (PowerShell / VS Code)

1. Download or clone this repository.
2. Open the project folder in VS Code.
3. Open **Terminal → New Terminal**.
4. (Optional) Create a virtual environment:

   ```powershell
   py -m venv venv
   .\venv\Scripts\Activate.ps1
   ```

5. Install dependencies:

   ```powershell
   py -m pip install -r requirements.txt
   ```

If PowerShell blocks virtual-environment activation, you can skip activation and use `py -m pip install -r requirements.txt` directly.

## Run the Project

### 1. Start the Pygame simulation

```powershell
py main.py
```

Controls:

| Key | Action |
|---|---|
| `I` | Switch to AI signal control |
| `F` | Switch to fixed-time control |
| `N` | Select normal traffic |
| `P` | Select peak traffic |
| `Esc` | Exit the simulation |

### 2. Run the controlled experiment

```powershell
py experiment.py
```

This runs the experiment configured in `experiment.py` and generates or updates the experiment results file. Check the terminal output and generated CSV for the actual results.

### 3. Open the Streamlit analytics dashboard

```powershell
py -m streamlit run dashboard.py
```

Streamlit normally opens a browser tab at `http://localhost:8501`. The dashboard reads `traffic_data.csv`, so run the simulation first if you need fresh simulation logs. If the dashboard reports missing data or columns, verify that the CSV was generated by the current version of the project.

## Simulation Data

The simulation logger records snapshot fields such as:

- `timestamp`
- `mode`
- `traffic_mode`
- `junction`
- `signal`
- `vehicles`
- `emergency_vehicles`
- `north_queue`, `south_queue`, `east_queue`, `west_queue`
- `cumulative_wait_frames`

The dashboard may convert cumulative waiting frames to seconds using the configured simulation frame rate. This is a conversion of the recorded metric, not necessarily the average waiting time per vehicle. Vehicle counts in snapshots should not be interpreted as the number of vehicles that completed their journeys.

## Tests

Run the included tests from the project root:

```powershell
py -m unittest test_agent.py test_routing.py
```

If the tests use a different test runner in your local version, follow the test files' setup.

## Notes and Limitations

- Results depend on the simulation configuration, random vehicle arrivals, and experiment settings.
- The CSV logs snapshots of the simulation; they do not automatically provide every possible metric, such as completed trips or individual vehicle travel times.
- A* routing is implemented for emergency-vehicle bypass behavior. The current CSV schema may not log every route decision.
- This is a simulation project and does not control real traffic infrastructure.
